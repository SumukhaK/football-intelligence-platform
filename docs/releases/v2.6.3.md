# Football Intelligence Platform — Release v2.6.3

**Version:** v2.6.3
**Release Date:** 2026-10-21
**Previous release:** [v2.6.0](v2.6.0.md)

The API jumps from 2.6.0 to 2.6.3 so that it matches the Android app, which shipped 2.6.1–2.6.3 on develop in the meantime. This release saves the favourite team to the account, hardens accounts after the 21 October backend audit, and carries the app's UX review polish. The full list is in the [changelog](../../CHANGELOG.md#263--2026-10-21).

---

## Added

- **The favourite team is kept on the account** ([#157](https://github.com/SumukhaK/football-intelligence-platform/pull/157), ADR 035). `GET` and `PUT /v2/me/preferences` save and restore it, so it comes back after a reinstall. A new account still goes through onboarding.

## Changed

- **The app's UX review polish** ([#160](https://github.com/SumukhaK/football-intelligence-platform/pull/160)). One colour scheme, a green status bar, sentence-case titles that match their tabs, no back arrow on Predict and Sign out on the account check. See [Android 2.6.3](frontend-2.6.3.md).
- **Projected Table and the assistant chat** ([#155](https://github.com/SumukhaK/football-intelligence-platform/pull/155), [#156](https://github.com/SumukhaK/football-intelligence-platform/pull/156)). See [Android 2.6.1](frontend-2.6.1.md) and [Android 2.6.2](frontend-2.6.2.md).

## Fixed

- **Account counters can't be outpaced** ([#161](https://github.com/SumukhaK/football-intelligence-platform/pull/161)). Failed sign-ins and strikes are changed in a Firestore transaction (a lock in the local JSON store), so parallel requests can't slip past the 5-try lockout or the 3-strike ban, even with more than one instance.
- **Ended sessions are deleted.** Sessions store `expires_at` as a timestamp, so a Firestore TTL policy removes them.
- **Probes stay responsive.** `/v2/live` and `/v2/ready` run on the event loop, so slow assistant calls can't delay them and get a healthy instance restarted.
- **Provider errors stay in the logs.** A failed assistant call answers 503 with a fixed message.
- **Bounded rate limiter memory.** Clients idle for a minute are dropped once 10,000 are tracked.

## Security

- certifi 2026.10.19 and Pillow 13.0.0 fix the advisories that failed pip-audit.

## Deploying

1. Add the sessions TTL policy (see the hosting tracker), then build and deploy as usual.
2. Check `/v2/ready`, and that `/v2/health` reports 2.6.3.
3. The Android 2.6.3 app needs this API: against 2.6.0 it stops at the account check.

## Still open

- A shared rate limiter, before Cloud Run runs more than one instance.
