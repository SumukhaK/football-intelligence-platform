# Football Intelligence Platform — Release v2.2.0

> Historical release/readiness record. Versions, commands, test totals and limitations below describe that milestone; use the [current quick start](../setup/quick-start.md) and [API reference](../api.md) for v2.6.0 setup and behavior.

**Version:** v2.2.0
**Release Date:** 2026-10-14
**Previous release:** [v2.1.0](v2.1.0.md)

A minor release that makes the project ready to host. The assistant now calls the prediction services as tools and answers season questions. The app gains crests, a My Team tab, invite-only sign-in and consent. The API now has structured telemetry, a container image, probes and a hosted model option. Every cloud feature is off by default, so the local setup runs as before. The API reports version 2.2.0 (it had stayed at 2.0.0 since v2.0.0). The full list is in the [changelog](../../CHANGELOG.md#220--2026-10-14).

---

## Added

- **Assistant tools** ([#65](https://github.com/SumukhaK/football-intelligence-platform/pull/65), ADR 018). The assistant calls the prediction, SHAP explanation and fixtures services, so it quotes the served model's numbers. `qwen2.5:7b-instruct` is the local default (ADR 019). Grounding and abstention evals check it.
- **Season questions** ([#76](https://github.com/SumukhaK/football-intelligence-platform/pull/76), ADR 021). The assistant can answer about results, head-to-heads, the next meeting and the league table on any date, with a goals-model projection for dates still ahead. A rule-based router answers player questions and questions about seasons that haven't started without calling the model.
- **App features** ([#73](https://github.com/SumukhaK/football-intelligence-platform/pull/73), [#74](https://github.com/SumukhaK/football-intelligence-platform/pull/74), [#80](https://github.com/SumukhaK/football-intelligence-platform/pull/80), [#83](https://github.com/SumukhaK/football-intelligence-platform/pull/83), ADRs 020 and 023):
  - Tap a fixture to predict it.
  - Team crests and league emblems.
  - Favourite-team onboarding and a My Team tab with a season outlook: the projected finish, and the chances of the title, the top four and relegation.
- **Invite-only accounts and consent** ([#79](https://github.com/SumukhaK/football-intelligence-platform/pull/79), [#84](https://github.com/SumukhaK/football-intelligence-platform/pull/84), ADR 022). Invites, sessions, a consent notice, bans and an owner script, plus the app's sign-in and consent screens. It is off locally (`AUTH_REQUIRED`). Accounts are kept in Firestore in the cloud ([#102](https://github.com/SumukhaK/football-intelligence-platform/pull/102), ADR 026).
- **Structured telemetry** (#87 to #92 and [#100](https://github.com/SumukhaK/football-intelligence-platform/pull/100), ADR 024):
  - Request IDs and JSON logs.
  - Contract events.
  - OpenTelemetry traces of retrieval, tool calls and generation.
  - Retries with backoff.
  - A local Grafana stack, plus Cloud Monitoring metrics and alerts stored as code.
- **Hosting readiness** (#95 to #99, [#103](https://github.com/SumukhaK/football-intelligence-platform/pull/103), ADR 025):
  - `/v2/live` and `/v2/ready` probes.
  - Verified serving snapshots.
  - A non-root container image that is built and probed in CI.
  - A Cloudflare Workers AI provider. Gemma 4 26B passes both assistant evals and has its own index.
- **Safety check for the beta** ([#113](https://github.com/SumukhaK/football-intelligence-platform/pull/113), ADR 027). Llama Guard 3 checks each question first. A harmful question gets a fixed refusal and a strike. The third strike bans the account.
- **Staging app build** ([#105](https://github.com/SumukhaK/football-intelligence-platform/pull/105)). Football Intelligence -stg installs beside the local app and calls the hosted API.
- **Dependency scans in CI** ([#107](https://github.com/SumukhaK/football-intelligence-platform/pull/107)). pip-audit and OSV-Scanner check the dependencies on every PR and once a week.

## Changed

- **Served model refit** ([#63](https://github.com/SumukhaK/football-intelligence-platform/pull/63), ADR 017). The model is refit on every season to 2025/26, with a dated 2026/27 backtest, bootstrap ranges and an Elo-only baseline.
- **Chat route** ([#86](https://github.com/SumukhaK/football-intelligence-platform/pull/86)). Chat runs in FastAPI's thread pool, so a slow answer no longer blocks other requests. Question text is no longer logged.
- **Hardening** ([#101](https://github.com/SumukhaK/football-intelligence-platform/pull/101)):
  - The rate limiter reads the real client address behind the proxy.
  - Request bodies and chat messages have size limits.
  - Every response sends a `nosniff` header.
  - On Cloud Run, the server refuses to start with unsafe settings.
- **App network** ([#106](https://github.com/SumukhaK/football-intelligence-platform/pull/106)). GET requests retry with backoff on 429 and 5xx responses. Release builds shrink their resources.
- **Docs and demo** (#110, #111). Every markdown file is brought up to date, with a new demo video and a project website. CONTRIBUTING and CODE_OF_CONDUCT are removed, and the licence is stated up front.

## Fixed

- The assistant's relevance cut-off now drops chunks that don't match the question ([#66](https://github.com/SumukhaK/football-intelligence-platform/pull/66)).
- The settings classes share `ai/.env` (#96), and `ASSISTANT_PROVIDER=off` turns the assistant off instead of stopping the server (#104).
- Release builds failed in R8, and now build again (#106). `assembleDebug` builds without a staging URL (#109).
- The Assistant screen keeps the message box above the keyboard, formats answers, and hides the confidence bar when an answer has no sources (#112).

## Build the Android app

Release APK/AAB downloads are no longer published. Build from source using the
[current Android guide](../../frontend/README.md#running-locally):

```sh
cd frontend
./gradlew assembleLocalDebug
adb install app/build/outputs/apk/local/debug/app-local-debug.apk
```

For an exact historical build, use the release tag and its Gradle task/output
layout. Older tags may predate flavors; follow that tag's build configuration. Staging builds require the configured
HTTPS URL and are shared privately with invited users.

## Upgrading

Install the new app build, and run `uv sync` in `ai/`. Local defaults are unchanged: no sign-in, the assistant on Ollama, the safety check off. Hosted deployments set the variables in `ai/.env.example`.
